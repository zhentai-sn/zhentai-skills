# 文档审查清单

按任务风险选择检查项，不要求每次机械执行全部内容。

## 单篇文档

### 目的与边界

- 标题能说明主题，不依赖目录猜测。
- 开头说明读者、目的、范围和当前状态。
- 结论、计划、假设和已实现事实有明确区分。
- 没有把另一个权威文档的大段正文复制过来。

### 正确性

- 路径、命令、配置名、环境变量和版本来自当前仓库。
- API、事件、模型和错误语义与 SDD、OpenAPI、代码或测试一致。
- 外部结论标注来源、日期和适用条件。
- 示例不会泄露真实凭据、租户、用户数据或内部 secret。

### 可执行性

- 前置条件、输入、步骤和成功信号完整。
- 风险操作包含验证、失败处理和回滚。
- 示例命令可复制，工作目录和占位符清楚。
- TODO 有所有者、下一步或关闭条件，而不是永久注释。

### 导航

- 从最近索引可以到达。
- 链接了直接上游依据和直接下游产物。
- 相对链接有效，标题锚点稳定。
- 被替代内容明确指向新文档。

## README 精简

- 一句话定位是否在首屏可见。
- 新读者能否沿最短路径完成第一次成功操作。
- 是否移除了完整架构、配置字典、全部 API 和长排障细节。
- 下沉内容是否按语义进入正确目录，而不是全部塞进一个 guide。
- README 的文档入口是否控制在少量高价值链接。

## 全仓库治理

- `docs/README.md` 是否解释目录职责和事实来源。
- 相同概念是否出现多个权威定义。
- 目录名和文件名是否表达内容而不是作者或临时时间。
- 活跃专题是否有索引，单文件目录是否过度分层。
- `todos/`、`open-issues/`、`reviews/` 等遗留目录是否有兼容说明。
- 完成状态是否有代码、测试、提交、决策或解决方案证据。
- 站点生成、CI 和外部链接是否依赖即将改变的路径。

## SDD 协作

- 已使用 `x-ai-sdd` 的模板、状态和追踪规则。
- plan 引用 SDD，而不是重新定义需求。
- guide 只给使用视角摘要，没有成为第二份接口契约。
- 行为变化同步更新验收标准和相关测试。
- 未实现需求没有在 README 或 guide 中写成当前能力。
- 仅迁移已有契约文字时只校验一致性，不因换位置自动推进 SDD 状态。
- 已区分 SDK 返回模型、HTTP response 与事件/流协议，没有误建全局 envelope。

## issue

- 新采用统一 `issues/` 模型时，frontmatter 包含唯一 `id`、合法 `type` 和合法 `status`；已有项目格式按仓库约定检查。
- 正文说明现状、影响、证据和下一步。
- decision 列出决策问题与约束，不预设未经同意的结论。
- review-finding 给出位置、风险和验收方式。
- done / superseded 状态链接关闭证据或替代项。

## 提交前

- 运行 `audit_docs.py` 和仓库已有文档校验。
- 查看 `git diff --check` 和目标文件 diff。
- 确认没有覆盖用户已有改动。
- 提交只包含一个可解释的文档实施单元。
- 提交主题与正文遵循仓库规则，不添加模型署名。
