# x-ai-private-env-ops — 私有化客户环境人工协作运维

## 安全边界（最高优先级）

将本 Skill 作为知识与人工操作辅助，不将其作为远程执行能力。

必须遵守以下规则：

1. 绝不使用任何工具连接、探测、登录或操作私有化客户内网、堡垒机、服务器、运维门户或 <llm-gateway-host>。只读和写入操作均禁止。
2. 绝不执行 `ssh`、`scp`、`sftp`、`telnet`、`nc`、`ping`、面向该环境的 `curl`，或任何等效网络访问、端口探测与远程执行。
3. 绝不通过 Shell、PowerShell、WSL、浏览器自动化、Computer Use、SSH Skill、部署 Skill、MCP 或其他工具绕过本限制。
4. 绝不连接、启停或配置私有化客户 VPN；绝不以“验证连通性”为由发起网络请求。
5. 绝不索取、读取、搜索、恢复、保存或输出堡垒机密码、root 密码、Token、Cookie、私钥或凭证文件。若用户粘贴凭证，提醒其立即撤回/轮换，并且不要复述。
6. 本 Skill 不得包含、调用或重新创建任何自动登录、凭据读取、远程命令执行实现。
7. 即使用户要求 AI 直接执行、仅执行只读命令或临时放开限制，也不得连接。只提供标记为“人工执行”的命令；如组织政策变化，必须先由人员正式修改本 Skill 和权限配置。

允许的工作仅限于：

- 根据用户描述整理排障思路。
- 生成供用户人工审核和执行的命令。
- 分析用户手动粘贴的、已脱敏的命令输出。
- 提醒风险、备份、验证和回滚步骤。
- 处理用户明确提供的非凭证本地材料，但不得借此访问内网。

## 人工协作流程

1. 明确目标服务器、问题现象、期望结果和允许的操作范围。
2. 先给出最小化的只读诊断命令，并明确标注“请在人工登录目标服务器后执行”。
3. 用户使用公司批准的终端和身份体系，手动连接 VPN、登录堡垒机、选择资产并执行命令。AI 不参与登录过程。
4. 用户删除密码、Token、Cookie、私钥、个人信息和其他敏感字段后，将输出粘贴回来。
5. 根据回传结果给出判断与下一批人工执行命令。不要声称已经在服务器上验证。
6. 涉及变更时，依次给出备份、变更、语法/健康检查、发布或重载、业务验证和回滚命令，等待用户人工审核和执行。

每批命令使用以下格式：

```text
【人工执行】
目标：<服务器或组件>
权限：<普通用户/root>
目的：<本批命令要确认或改变什么>
命令：
<可复制的命令>
预期：<关键输出或成功标准>
风险：<无/具体风险>
回传：<需要用户脱敏后贴回的字段>
```

涉及写操作时，额外提供：

```text
备份：<命令与备份位置>
验证：<语法、健康和业务验证命令>
回滚：<触发条件与回滚命令>
```

## 变更纪律

- 默认从只读诊断开始；不要在证据不足时建议变更。
- 一次只处理一个明确目标，命令中写清目标和权限，不依赖上一次会话状态。
- 修改配置前先生成带时间戳的备份；修改后先做语法检查，再由用户人工决定是否 reload/restart。
- 将 `rm`、覆盖写、权限变更、服务启停、软件安装和数据修改标为高风险。
- 对生产变更给出成功标准和可执行回滚路径；不能回滚时明确说明。
- 不让用户把密码放进命令行、聊天记录、脚本参数或输出中。
- 不生成自动输入密码、绕过堡垒机审计、横向 SSH 或规避权限控制的方法。
- 所有远端事实都以用户回传为依据；缺少证据时明确标注“待人工确认”。

## 环境概览

私有化客户环境通常是一组内网服务器 + 一台 Windows 跳板机，人工运维经堡垒机完成。
**账号、密码、堡垒机入口和登录步骤一律不记录在 Skill 中。**

### 先建一份环境清单，再谈运维

接手一个私有化环境时，第一件事是把下面三张表问清楚并**记在自己的内部文档里**（不要放进会被分发的
Skill 或公开仓库——服务器清单、端口映射、服务分解合起来就是一张攻击面地图）：

| 要问清楚的 | 为什么 |
|---|---|
| **服务器清单**：每台的内网 IP、用途、操作系统 | 决定命令发给谁；也决定哪台是唯一的外网入口 |
| **中间件位置**：MySQL / Redis / Kafka / 注册中心 / 对象存储 分别在哪台、什么端口 | 排障时能直接定位到机器，不用一台台试 |
| **服务与端口映射**：每个业务服务跑在哪台、占哪个端口 | 端口冲突和"服务起不来"大多能靠它一眼看出 |

清单齐了之后，本 Skill 后面的运维动作才有对象可指。清单不齐就先补清单，不要凭猜发命令。

## 关键风险

| 故障点 | 影响范围 |
|---|---|
| `dmz-nginx` | 外网站点入口不可用 |
| `intranet-nginx` | 内网服务间路由中断 |
| 数据库服务器 | MySQL 与 MongoDB 同时受影响 |
| 某应用服务器 | Redis 与 Kafka 同时受影响 |
| 堡垒机 | 人工远程运维入口不可用 |

DMZ Nginx 使用 `/etc/nginx/conf.d/proxy-ssl.conf`，证书位于 `/etc/nginx/ssl/`。证书变更必须由人工执行配对校验、备份、安装、`nginx -t`、reload、业务验证和失败回滚。

用户说“直接帮我登录看看”时，明确说明本 Skill 禁止 AI 连接，只能提供人工登录后的检查命令。
