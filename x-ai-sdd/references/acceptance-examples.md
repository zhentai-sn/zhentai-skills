# 验收标准好/坏对照

§15 验收标准必须可验证。**含糊不能写。**

## 通用原则

1. 能写成一条测试用例或一次可执行的手动验证步骤。
2. 给出"触发条件 + 预期结果"，不写"应该 / 正常 / 合理"。
3. 涉及异步、回调、消息时，必须给可观测信号（trace_id、日志字段、事件名）。
4. 涉及前端时，必须指定具体状态分类（空 / 加载中 / 异常 / 权限不足）。
5. 涉及算法时，必须给评估指标和阈值。

## 后端示例

| 不推荐 | 推荐 |
| --- | --- |
| 报告数据正常同步。 | 同一 `report_id` 在 5 分钟内重复推送时，库中只产生 1 条记录，且后续推送返回 200。 |
| 接口稳定。 | 单实例 200 QPS 持续 10 分钟，P99 < 300ms，错误率 < 0.1%。 |
| 失败有日志。 | 推理失败时，记录 `error_code` / `trace_id` / `model_version` 三字段，可在 Langfuse 按 `trace_id` 查到。 |

## 事件 / 异步示例

| 不推荐 | 推荐 |
| --- | --- |
| 事件能消费。 | 同一 `event_id` 重复消费 3 次，下游表只产生 1 条副作用记录。 |
| 消费失败会重试。 | 消费抛异常时，进入 DLQ，记录 `event_id` 和 `consumer_group`，并可通过 admin 接口手动重放。 |

## 前端示例

| 不推荐 | 推荐 |
| --- | --- |
| 页面展示正常。 | 接口返回空数组时，展示"暂无数据"占位图，不展示骨架屏，也不展示错误提示。 |
| 筛选好用。 | 筛选条件改变后浏览器刷新，URL query 保留筛选条件，分页回到第 1 页。 |
| 错误处理友好。 | 接口 5xx 时展示 Toast "服务暂时不可用，请稍后重试"，按钮 5 秒后可重试。 |

## 算法示例

| 不推荐 | 推荐 |
| --- | --- |
| 模型效果好。 | 在 dataset `intent-v3` 上，意图识别 macro-F1 ≥ 0.82。 |
| 回调正确。 | 算法回调缺少 `trace_id` 或 `model_version` 字段时，服务返回 400 并不写库。 |
| 版本可切换。 | 通过配置 `model_version=v2.1` 上线后，所有新请求使用 v2.1；正在进行的请求按发起时的版本完成。 |

## 数据 / 幂等示例

| 不推荐 | 推荐 |
| --- | --- |
| 不会重复写。 | 同一 `(tenant_id, business_key)` 重复写入时，DB 唯一索引拒绝，服务返回既有记录的 ID。 |
| 字段对齐。 | `user.gender` 仅允许 `male / female / unknown` 三个值，写入其他值时返回 422 并附 `field_errors`。 |
