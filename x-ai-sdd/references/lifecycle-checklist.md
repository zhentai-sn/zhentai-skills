# 生命周期转入清单

每次推进 SDD 状态前，按对应分支逐项确认。任何一项不满足 → 不允许推进。

## draft → ready

> ready 的含义：可以作为 AI 编码约束输入；任何按此 SDD 写出的代码都应可被 §15 验收。

- [ ] §0 文档状态字段齐全（状态、当前阶段、关联主 SDD、负责人、最后更新）。
- [ ] §1 / §2 写清楚负责什么 / 不负责什么，没有"什么都管"。
- [ ] §3 当前阶段目标已收敛到本次交付。
- [ ] §4 输入来源每项有字段、协议、约束。
- [ ] §5 输出结果每项有字段、协议、约束。
- [ ] §6 核心流程主链路可读，不依赖代码理解。
- [ ] §9 涉及的新表 / 字段 / 接口 / 事件 已全部出现在 §8 / §9 / §12。
- [ ] 涉及多表关联、跨库逻辑键或状态类表时，§8 / §9 已提供 Mermaid ER 图，并明确
      物理外键与逻辑关联。
- [ ] 每张新增或修改表的数据字典包含类型、可空、默认值、键/约束、索引、用途和数据来源。
- [ ] 跨存储数据流和复杂状态流转分别在 §6 / §11 提供对应 Mermaid 图。
- [ ] §10 幂等规则明确：同步接口注明幂等键；异步消费必须有。
- [ ] §14 引用的其他 SDD 路径有效。
- [ ] §15 验收标准每条可验证（对照 `acceptance-examples.md`）。
- [ ] §17 待确认问题为 0，或全部转入 §16 决策记录。

## ready → implemented

> implemented 的含义：代码已实现，且与 SDD 对齐。

- [ ] 代码所有新增/修改的表、接口、事件、字段都能在 SDD §8/§9/§12 找到对应描述。
- [ ] 实现过程中改动过的设计已反补回 SDD。
- [ ] §15 验收清单逐项自查，列出"已完成 / 未完成 / 无法验证"三类。
- [ ] §16 决策记录已补齐实现期的关键决策。
- [ ] §0 最后更新时间已更新。

## implemented → accepted

> accepted 的含义：验收通过。状态由 SDD §0 表达；是否移动文件由项目覆盖层决定。

- [ ] §15 验收标准全部通过，未通过项必须有专门跟进 issue/任务。
- [ ] 若项目覆盖层启用了归档目录，Feature SDD 已按项目约定迁移；默认 `feats/` 结构不移动文件。
- [ ] 团队 `README.md` 索引同步更新。
- [ ] 若产生了可复用的通用规则，已反补到主 SDD（不是把 Feature SDD 全文复制过去）。
- [ ] §0 状态字段更新为 accepted，最后更新时间填验收日期。

## 任意状态 → 弃用 / 重写

> 不允许直接删除。

- [ ] §0 状态加注 `superseded` 或 `deprecated`。
- [ ] 在文档顶部注明替代 SDD 的路径与替代理由。
- [ ] 若有 archived 同名 Feature SDD，保留以备追溯。
